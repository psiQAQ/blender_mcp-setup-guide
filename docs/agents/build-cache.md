# 本地构建成果与缓存

仓库只保留一套当前成果，位于被忽略的 `build/latest/`。构建、测试和网站入口使用 `scripts/build_cache.py`，临时工作目录位于 `build/.working/`，结束后删除。

原生集成检查由外层进程创建工作目录，再在子进程执行。子进程退出并释放 SDK 原生模块后，外层进程导出报告、日志与截图，再清理运行环境。

| 内容 | 保留位置与范围 |
| --- | --- |
| 候选包及来源 | `dist/`，成功校验后替换；包内记录提交和 dirty 状态 |
| 网站 | `site/`，完整生成后替换；失败保留旧网站并标记其来源 |
| 验证报告 | 根目录 `*-tests.json`，绑定实际包 SHA-256；候选替换只使同一输出目录中被替换包的报告失效，其他发布线及发布基线证据保留 |
| 日志与截图 | `evidence/<检查>/`，导出当前诊断；重试前将 Failed 报告与必要诊断按内容哈希保留在 `evidence/failed-checks/`，不保留运行环境 |
| 构建输入 | `inputs/`，每种平台/角色只保留当前锁定版本；最低版本与当前版本属于独立必需角色 |
| 保留与清理记录 | `maintenance/`，记录来源、迁移哈希、清理目标和剩余空间 |
| 当前状态 | `status.json`，区分本次操作提交与旧成果提交；失败不能复用 Passed |

临时目录的持久日志必须先导出，再删除运行环境。占用或权限拒绝的对象保留并报告，不修改 ACL 或接管所有权。清理函数拒绝工作区外路径、build 根目录和指向外部的链接。并行 runner 使用各自独立 checkout；同一 checkout 的构建入口依次运行。

原生文件诊断只保留最新一份完整 ETL，可使用 `scripts/compact_native_trace.py` 保存 gzip 归档，确认解压后的全部字节 SHA-256 与原记录一致后才删除原文件。较早记录保留摘要、统计与原始哈希。可重建的事件导出在关联摘要核对来源哈希后清理，最新完整记录、报告与清理清单必须保留；不能用事件数量相似代替记录的完整字节校验。

更新 wheel 锁后，下次构建按锁文件哈希替换旧输入。`--wheelhouse` 指定的外部输入由调用者管理；默认缓存使用已验证的当前 wheels。官方子模块、仓库 `.git`、系统 Blender 和远端发布资产不属于 build 缓存。

长期说明和素材来源放在 `docs/references/`，可复用工具放在 `scripts/`。原始下载 ZIP 继续忽略。历史任务文字中的旧 build 路径是历史来源，不代表应重新建立这些目录。

对已有历史目录进行集中整理时，先建立保留清单，复制必要文件并逐项核验 SHA-256，再运行 `scripts/clean_build.ps1`。该脚本只清理清单中的 build 直接子项，保留 `latest` 和 `.working`，把未删除对象及总字节数写入当前维护记录。完成后确认工作目录为空、当前输入匹配锁、报告与实际候选包一致；重新运行入口后仍满足这些条件。
